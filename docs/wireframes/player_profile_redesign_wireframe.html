Data Coverage + Trust

Make the stats feel safe

This card should appear before advanced metrics so the player knows what is complete, what is partial, and what is deliberately hidden.

  • Scorecard-safe: matches, runs, wickets, averages, catches, high score, BBI, 30s, 3WI and 5WI can use complete scorecard/aggregate sources.
  • Verified ball-by-ball: Bat SR from balls, dot percentage, boundary rate, phase metrics, fastest innings and tandems must use only matched delivery data.
  • Coverage example: Vinay has 19 verified ball-by-ball batting innings in the deploy-safe Hall of Fame summary, so rate cards should clearly label that subset.
  • Missing coverage: show a premium empty state, not 0.0%, and never mix all-scorecard runs with ball-by-ball denominators.

Wireframe Notes

Opinionated implementation notes for the eventual real app build.

Keep

Core profile trust

  • Search and canonical player profile links.
  • Career snapshot, Player vs Peers, trends, tables and Milestone Watch.
  • Scorecard links where a match-level record is proven.
Reorder

Story before audit

  • Identity hero and DNA cards first.
  • Advanced insight cards before detailed history tables.
  • Raw breakdown tables near the bottom.
Remove or hide

Less clutter

  • Duplicate KPI blocks that repeat the hero stat strip.
  • Bowling-only modules for non-bowlers.
  • Ball-by-ball metrics when verified coverage is missing.
